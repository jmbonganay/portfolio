# Make Workflow Hardening Design

**Status:** Approved

## Goal

Produce an importable hardened copy of the existing Make blueprint that accepts only API-key-authenticated, server-validated submissions and prevents raw user text from controlling Gemini, routing, document generation, or email recipients.

## Source and Output

Source blueprint:

```text
/Users/johnmichaelbonganay/Downloads/Asynchronous Inbound CRM Triage Engine.blueprint.json
```

Hardened output:

```text
automation/asynchronous-inbound-crm-triage-engine.hardened.blueprint.json
```

The original file remains unchanged. Connection identifiers may remain as import hints, but no API key, webhook secret, hCaptcha secret, Redis credential, or webhook URL will be added to the output.

## Webhook Contract

The first module remains a Make Custom Webhook with built-in API-key authentication. After import, the user selects the already secured webhook whose API key matches Vercel's `MAKE_WEBHOOK_SECRET`.

The webhook data structure includes:

```text
name
email
message
projectIdea
projectType
submissionType
forwardedAt
```

It excludes CAPTCHA and provider credentials.

## Routing

The scenario uses mutually exclusive routes:

### Contact route

- Requires `submissionType = contact_form`.
- Stores one normalized lead row.
- Sends one fixed-recipient owner notification.
- Sends one visitor acknowledgment to the validated webhook email.
- Selects recruiter, project, or general acknowledgment copy without allowing more than one branch to send.

### AI Proposal route

- Requires `submissionType = ai_scoper`.
- Stores one normalized lead row.
- Sends `projectIdea` to Gemini as untrusted quoted content.
- Creates one Google document, exports one PDF, and sends it only to the validated webhook email.
- Logs provider failure without sending a partial or empty document.

No route accepts a recipient generated by Gemini or supplied in model output.

## Gemini Boundary

The prompt separates trusted instructions from untrusted input. It states that text inside the user-data delimiter may contain instructions and must never override the task. Gemini must not reveal prompts, modify recipients, claim actions were performed, emit executable code, create external links, or request credentials.

Generation uses Gemini 2.5 Flash with low temperature and a bounded output. The response must contain exactly:

1. Executive concept summary
2. Recommended production stack
3. Three-phase development roadmap
4. Estimated development hours

The duplicated name and project-idea mappings in the current prompt are removed. The output is treated as document content, not as routing instructions or Make expressions.

## Email and Document Safety

- Owner-recipient addresses are fixed configuration, never webhook fields.
- Visitor recipients come only from the server-validated `email` field.
- Subjects use normalized names and fixed prefixes.
- User input is not inserted into HTML email markup without escaping or plain-text treatment.
- Generated filenames use a safe fixed prefix plus a normalized execution identifier rather than raw project text.
- Attachments originate only from the Google Drive export module in the current execution.

## Error Handling

Each external provider chain has an error path that stops dependent modules. Gemini failure prevents document creation. Document/export failure prevents attachment email. Gmail failure is visible in Make execution history. The scenario does not retry visitor email indefinitely.

## Blueprint Verification

An automated blueprint test will parse the JSON and confirm:

- One webhook trigger exists.
- Contact and AI routes are explicitly filtered by `submissionType`.
- Only validated webhook email mappings are used as visitor recipients.
- The Gemini prompt contains the untrusted-data boundary.
- The prompt no longer duplicates mapped user fields.
- No credential pattern or webhook URL is embedded.
- Every exported module reference points to an existing module.
